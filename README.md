# Рацион · Daily Nutrition

Семейный план питания в тёплой тёмной палитре: личные порции, общее меню и корзина с названиями продуктов на русском и испанском.

**Приложение:** https://grachia-m.github.io/daily-nutrition/  
**Репозиторий:** https://github.com/grachia-m/daily-nutrition

## Возможности

- Вход и регистрация по email и паролю через Supabase Auth; выход с иконкой в верхней панели и настройках.
- Русский, английский и испанский интерфейс: встроенные рецепты, продукты, поиск, календарь и выгрузки. Язык сохраняется в аккаунте и на устройстве; пользовательский текст не переводится.
- Отдельные аккаунты с приватными данными и синхронизацией устройств.
- До восьми семейных профилей: личные цели, вес, рост, возраст, активность, тренировки, вода и дневник.
- Общий план на день, неделю и месяц; замена блюда через поиск в той же категории.
- 25 встроенных рецептов и собственные рецепты аккаунта.
- Пропорции по людям, общая корзина, CSV, JSON для переноса и восстановления.
- Редактор рецептов: разбор состава в граммах, свои продукты по этикетке, расчёт КБЖУ.
- Необязательный экспериментальный AI-помощник для черновика шагов приготовления.

## Локальная разработка

Нужны Node.js 22+ и Python 3. Зависимости npm не требуются.

```sh
npm test
npm run check
npm start
```

Открыть http://localhost:4173 . `npm run build` обновляет каталог `docs/` для GitHub Pages. После правок нужно пересобрать `docs/` и закоммитить его вместе с исходниками. GitHub Pages публикуется из `main` → `/docs`, без сервера и без секретов в GitHub Actions.

## Настройка Supabase

Рабочий проект: `daily nutrition`, ref `xopllxerdxqlbhfwupeh`. База уже подготовлена. В `database/schema.sql` сохранён точный DDL для обзора; на существующем проекте не выполняйте его повторно — таблицы уже есть.

В `dist/config.js` находятся URL проекта и **publishable key**. Этот ключ предназначен для браузера и не является секретом. Ключи `service_role`, секретные ключи и пароли не нужны клиентскому коду и не должны попадать в репозиторий. Если используются другие значения, затем выполните `npm run build`.

В **Supabase → Authentication → URL Configuration**:

- Site URL: `https://grachia-m.github.io/daily-nutrition/`.
- Redirect URLs: этот же адрес и `http://localhost:4173/` для разработки.

Email/password и регистрация включены; подтверждение email остаётся включённым. После регистрации пользователь подтверждает письмо, затем входит в приложение. Встроенная почта Supabase подходит для ограниченного тестирования и может ограничивать получателей; для регистрации произвольных пользователей настройте собственный SMTP в Authentication. Не отключайте подтверждение email ради обхода настройки почты.

Приложение показывает ошибку отправки письма и не изображает успешный вход без сессии. Полный цикл реальной регистрации требует доступного SMTP/подтверждения пользовательского email; почтовые настройки следует проверить при запуске.

## Данные и доступ

Пароли хранит Supabase Auth. Приложение не сохраняет введённые пароли. SDK хранит сессию; аккаунт используется для всех обращений к базе.

| Таблица | Назначение |
| --- | --- |
| `account_settings` | Имя аккаунта, язык, часовой пояс, активный участник, полный снимок плана и версия синхронизации |
| `family_members` | Личные параметры участников и архив удалённых профилей |
| `meal_plans` | Замены по дате и приёму пищи |
| `intake_logs` | Снимки фактически съеденных порций |
| `hydration_entries` | Вода по человеку и дате |
| `recipe_portions` | Личные количества ингредиентов привычных блюд |
| `shopping_checks` | Отметки купленных продуктов |
| `custom_foods` | Свои продукты и КБЖУ на 100 г |
| `custom_recipes` | Личные рецепты, состав и шаги приготовления |

На всех таблицах включён RLS: `auth.uid() = user_id`. Анонимам таблицы и функции синхронизации недоступны. Функции `load_nutrition_state` и `save_nutrition_state` работают как `SECURITY INVOKER`, с правами вошедшего пользователя.

Сохранение обновляет снимок и все связанные таблицы одной транзакцией. Проверяется номер версии: изменения другого устройства не перезаписываются молча. При конфликте остаётся локальная копия; её можно экспортировать или загрузить облачную версию. Перед загрузкой облака локальная версия сохраняется в сессии браузера и доступна через «Вернуть копию до загрузки».

При потере сети изменения остаются в локальной копии аккаунта. В настройках можно повторить синхронизацию. Копии разделены по идентификатору пользователя и не подхватываются автоматически другим аккаунтом. Старый рацион без аккаунта переносится отдельной кнопкой «Перенести прежний рацион». JSON версий 1–3 мигрируется в версию 4.

## Свои рецепты и AI

В разделе «Рецепты» нажмите «Добавить свой рецепт»:

1. Введите название, приём пищи и время.
2. Добавьте продукты: например, `куриное филе 200 г`, `рис 80 г`.
3. Нераспознанные продукты внесите по этикетке: названия на двух языках и КБЖУ на 100 г.
4. Напишите шаги или отдельно запустите AI-помощника.
5. Проверьте рецепт и сохраните. Он появится в вашем каталоге, замене блюд и корзине.

Калории и БЖУ считаются арифметически из продуктов и граммовок. Модель не используется как источник нутриентов. Без известных продуктов и веса надёжный расчёт невозможен; приложение просит уточнение вместо угадывания.

Помощник использует `onnx-community/Qwen3-0.6B-ONNX` через Transformers.js 3.8.1, WebGPU и `q4f16`. Загрузка начинается **только по нажатию кнопки** и может потребовать сотни мегабайт и заметное время. Во время подготовки данные рецепта обрабатываются на устройстве. Браузер скачивает библиотеку и веса с CDN/Hugging Face. Без WebGPU или при ошибке модели рецепт можно составить вручную. Качество черновика зависит от модели; шаги требуют проверки. Выполнение модели на пользовательском GPU не входит в автоматические проверки.

Документация: https://huggingface.co/onnx-community/Qwen3-0.6B-ONNX и https://huggingface.co/docs/transformers.js/guides/webgpu . Локальная небольшая модель здесь — удобство ввода, а не условие работы приложения. Для стабильного сервиса на слабых телефонах возможен отдельный серверный inference, но он потребует выбранного провайдера и бюджета; сейчас он не подключён.

## Расчёты питания

Начальные цели и параметры — примеры, не персональные рекомендации. Рост и возраст вводятся самостоятельно. Дополнительная оценка калорий использует Миффлина — Сан Жеора и выбранную активность; ручная цель остаётся доступной.

Ингредиенты указаны сырыми, крупы — сухими, яйца — без скорлупы. Пищевая ценность приблизительная, кроме явно указанных данных упаковки. Корзина не округляет до упаковок и не добавляет запас на очистку. У готовых продуктов вес изменяется: для общей готовки соблюдайте индивидуальные количества каждого компонента.

В омлетах отдельно считаются целые яйца и дополнительный жидкий белок. В ночных завтраках можно сохранить разные количества молока и по 15 г протеинового порошка: масса порошка не равна массе чистого белка. В вечернем варианте Philadelphia Cottage используются 87,5 г на человека — половина тары 175 г. Источники продуктов и иллюстраций приведены в карточках.

Источники формулы и продукта: https://pubmed.ncbi.nlm.nih.gov/2305711/ , https://philadelphia.eu/es/productos/philadelphia-cottage-cheese-43458/ , https://www.dia.es/quesos/fresco/p/310747 .

## Проверка

`npm test` также проверяет все переводы встроенного каталога, три языка интерфейса, поиск и ввод ингредиентов на английском и испанском, сохранность данных при переключении языка и выход с обработкой ошибок.

`npm test` запускает проверки календаря, порций и корзины, фиксированных личных количеств, удаления/восстановления участников, миграции, пользовательских рецептов, разбора ингредиентов, экранирования текста, очереди синхронизации и конфликтов версий.

Дополнительно в Supabase проведён транзакционный тест с двумя временными пользователями: сохранение/загрузка, проекции, запрет чтения и записи чужих строк, запрет анонимного доступа и защита от перезаписи устаревшей версии. Транзакция откатилась, тестовые аккаунты не остались. Проверки security/performance advisors не обнаружили замечаний после исправления прав внутренней функции события RLS.

В браузере проверены загрузка SDK, форма входа и переключение регистрации. Реальная почтовая регистрация и генерация на GPU требуют дополнительной проверки на целевом устройстве.
